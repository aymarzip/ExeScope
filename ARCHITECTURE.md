# Архитектура ExeScope

Инструмент динамического анализа подозрительных Windows-бинарников в изолированных средах. Ниже описаны архитектурные слои, модель данных, управление привилегиями и защита от системных краевых случаев Windows.

## 1. Компоненты системы

Система разделена на четкие слои:

```
┌────────────────────────────────────────────────────────┐
│                   ExeScope.UI (WPF)                    │
│    MVVM: MainViewModel, Converters, Views, DataGrids   │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│                  ExeScope.Engine                       │
│ ┌────────────────────────────────────────────────────┐ │
│ │ AnalysisSessionManager (Координатор сессии)        │ │
│ └─────────┬──────────────────────────────┬───────────┘ │
│           │                              │             │
│ ┌─────────▼──────────────┐   ┌───────────▼───────────┐ │
│ │ ProcessCorrelation     │   │ FileArtifactCollector │ │
│ │ Engine (PID+StartTime) │   │ (Квоты, хеши, копии)  │ │
│ └─────────┬──────────────┘   └───────────┬───────────┘ │
│           │                              │             │
│ ┌─────────▼──────────────────────────────▼───────────┐ │
│ │ Сборщики событий (IEventCollector):                │ │
│ │  - EtwEventCollector (Kernel File/Registry/Net)    │ │
│ │  - PollingProcessWatcher (Toolhelp32 / модули)     │ │
│ │  - NetworkConnectionTracker (GetExtendedTcpTable)  │ │
│ │  - RawSocketCapture + PcapngWriter (PCAPNG)        │ │
│ └─────────┬──────────────────────────────────────────┘ │
│           │                                            │
│ ┌─────────▼──────────────────────────────────────────┐ │
│ │ Хранилище и отчеты:                                │ │
│ │  - FileSessionStorage (BoundedChannelQueue)        │ │
│ │  - HtmlReportGenerator (Автономный HTML)           │ │
│ └────────────────────────────────────────────────────┘ │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│                   ExeScope.Core                        │
│    Модели событий, Диагностика, PathSanitizer,         │
│    HashHelper, AuthenticodeHelper, BoundedChannelQueue │
└────────────────────────────────────────────────────────┘
```

- **ExeScope.Core**: доменные модели событий (`AnalysisEvent`, `FileEvent`, `ProcessEvent`, `RegistryEvent`, `NetworkEvent`, `InjectionEvent`), перечисление техник внедрения `InjectionTechnique`, утилиты хеширования SHA-256, проверка цифровых подписей WinTrust Authenticode, кольцевой буфер и санитизация путей.
- **ExeScope.Engine**: координатор сессий (`AnalysisSessionManager`), корреляция процессов (`ProcessCorrelationEngine`), детектор инъекций (`InjectionDetector`), сборщики телеметрии (ETW, Toolhelp32, IP Helper, Raw Sockets) и потоковая сериализация данных на диск.
- **ExeScope.UI**: графический интерфейс на WPF (MVVM, виртуализация строк в DataGrid, реактивная фильтрация и поиск, вкладка «Инъекции» и визуализация скомпрометированных узлов в дереве процессов).
- **ExeScope.TestTarget**: тестовое консольное приложение для функциональной и нагрузочной проверки всех подсистем анализатора (включая симуляцию сброса DLL и вызова внешнего загрузчика).

## 2. Системные особенности Windows и их обработка

### Модель привилегий (Admin vs Standard User)
Трассировка системных событий ядра через Windows Kernel ETW (`Microsoft-Windows-Kernel-File`, `Registry`, `Network`) требует прав локального администратора.
- Основной интерфейс анализатора по умолчанию работает в непривилегированном контексте (`requestedExecutionLevel level="asInvoker"`).
- При старте анализатор проверяет членство текущего токена в группе `Builtin\Administrators`.
- Если прав администратора нет, приложение переходит в fallback-режим: дерево процессов строится через Toolhelp32 и снапшоты модулей, сетевые соединения отслеживаются через `GetExtendedTcpTable`, а артефакты копируются из доступных пользовательских директорий.
- При запуске от администратора активируется сессия `KernelTraceEventParser.KernelSessionName` (`NT Kernel Logger`), предоставляющая субмиллисекундный поток событий ввода-вывода файлов и обращений к реестру.

### Защита от переиспользования PID (PID Recycling)
В Windows идентификаторы процессов активно переиспользуются ядром сразу после закрытия последнего дескриптора завершенного процесса.
- Чтобы исключить ложную привязку чужих событий, процессы идентифицируются парой `(PID, StartTimeUtc)`.
- Движок корреляции сопоставляет метку времени события с интервалом жизни конкретного процесса.
- Повторные запуски целевого бинарника выявляются и выносятся в новые отдельные сессии.

### Разделение журнала операций и содержимого файлов
Низкоуровневые события файловой системы в ETW фиксируют факт операции (путь, смещение, число запрошенных байт, код возврата NTSTATUS), но не передают само тело файла в поток трассировки.
- Каждое событие `FileEvent` содержит признак `HasCapturedBytes = false`.
- Для сохранения файлов задействуется модуль `FileArtifactCollector`:
  - Копируются только созданные или измененные целевыми процессами файлы.
  - Действует белый список каталогов (по умолчанию исключены служебные каталоги Windows и Program Files).
  - Установлены квоты на размер отдельного файла (10 МБ по умолчанию) и общий бюджет сессии (100 МБ).
  - Копирование выполняется в неблокирующем режиме (`FileShare.ReadWrite | FileShare.Delete`).
  - При несовпадении хеша в процессе чтения фиксируется флаг `MightHaveChangedDuringCopy`.

### Сетевой перехват и приватность
Сырой перехват пакетов через raw-сокеты или promiscuous-драйвер видит трафик всей системы.
- Захват PCAPNG по умолчанию выключен.
- При включении трафик фильтруется: в файл попадают только пакеты, локальный порт которых привязан к отслеживаемым процессам.
- TLS/HTTPS сохраняется исключительно в зашифрованном виде без попыток подмены сертификатов или MITM.

### Безопасность путей (Path Traversal)
Исследуемые приложения могут генерировать пути с переходами каталогов (`../../`), потоками NTFS (`:stream`) или зарезервированными именами DOS (`CON`, `NUL`, `COM1`).
- `PathSanitizer` валидирует и нормализует все входящие пути.
- Имена артефактов очищаются от запрещенных символов.
- Метод `CreateSafeArtifactDestination` проверяет канонический путь с замыкающим разделителем каталога, гарантируя, что ни один файл не выйдет за пределы каталога сессии.

### Детекция инъекций и анализ загрузчиков читов (Minecraft Anti-Cheat / DLL Injection)
Вредоносные дропперы и инжекторы читов (особенно в экосистеме Minecraft) часто не выполняют опасных действий в своем основном процессе:
- Загрузчик распаковывает нативную DLL во временную папку (`%TEMP%`, `%APPDATA%`), находит целевой запущенный процесс (`javaw.exe`) и внедряет библиотеку стандартными вызовами `LoadLibrary`, удаленными потоками (`CreateRemoteThread`) или ручным маппингом.
- Модуль `InjectionDetector` реализует алгоритм корреляции на уровне ядра:
  1. `EtwEventCollector` слушает ключевые слова ядра `ImageLoad` и `Thread` наряду с `FileIO`.
  2. При записи файла с расширением `.dll`, `.exe`, `.sys` отслеживаемым процессом, событие сохраняется в скользящем окне корреляции (`_recentDllWrites`, 30 секунд).
  3. Когда во внешнем процессе (не входящем в отслеживаемое дерево) фиксируется системное событие `ImageLoad`, детектор сопоставляет путь к модулю с недавними записями.
  4. При совпадении путей регистрируется факт `DllInjection`, генерируется `InjectionEvent`, сохраняются PID источника и цели.
  5. Внедренный файл немедленно ставится в очередь `FileArtifactCollector` для гарантированного копирования в каталог `artifacts/` до того, как инжектор попытается его стереть.
  6. При включенном параметре `TrackInjectionTargetEvents` целевой процесс автоматически регистрируется в `ProcessCorrelationEngine` с флагом `IsInjectionTarget`, привязывается к источнику инъекции в дереве процессов, и его последующие файловые, реестровые и сетевые события включаются в телеметрию сессии.
  7. Эвристика ручного маппинга (`ManualMapping`): детектор перехватывает запуск удаленного потока (`ThreadStart`) во внешнем процессе без предшествующего `ImageLoad`.

## 3. Производительность и буферизация

- **Канал с ограниченной емкостью (`BoundedChannelQueue<T>`)**: все сборщики передают события в канал с вытеснением старых записей (`DropOldest`) при перегрузке. Счетчик потерь передается в интерфейс в реальном времени.
- **Пакетная запись на диск**: фоновый воркер сбрасывает накопившиеся события пачками по 1000 записей либо по тайм-ауту 150 мс.
- **Пакетные обновления интерфейса (`BulkObservableCollection<T>`)**: вставка данных в коллекции GUI выполняется пачками с вызовом одиночного уведомления `Reset`, что исключает лавину обновлений в UI-потоке WPF.
- **Виртуализация отображения**: для DataGrid в XAML включен режим `VirtualizingPanel.VirtualizationMode="Recycling"`, позволяющий комфортно просматривать списки на сотни тысяч элементов.
