# Руководство пользователя ExeScope

## 1. Назначение и предупреждение безопасности

**ExeScope** — это специализированное приложение для наблюдения за поведением исполняемых файлов (`.exe`) в Windows во время их запуска и работы.

> ⚠ **ВАЖНОЕ ПРЕДУПРЕЖДЕНИЕ ПО БЕЗОПАСНОСТИ:**
> ExeScope **НЕ является изолирующей песочницей** и не изолирует операционную систему от разрушительных действий исследуемого приложения!
> Всегда запускайте ExeScope и исследуемые файлы **исключительно внутри чистой тестовой виртуальной машины** (например, VirtualBox, VMware, Hyper-V или Windows Sandbox):
> * Перед запуском создайте снимок (Snapshot) состояния виртуальной машины.
> * Убедитесь, что внутри виртуальной машины отсутствуют личные учетные записи, рабочие пароли, токены и конфиденциальные документы.
> * Отключите сетевые общие папки хост-машины.
> * После завершения исследования всегда откатывайте виртуальную машину к исходному снимку.

---

## 2. Системные требования

* **ОС:** Windows 10 (версия 1809+) или Windows 11 (x64 / ARM64).
* **Среда выполнения:** .NET Desktop Runtime 8.0 (или .NET 8 SDK для сборки из исходников).
* **Привилегии:**
  * *Обычный пользователь:* доступен сбор иерархии процессов, сетевых сокетов и сохранение созданных файлов.
  * *Администратор:* дополнительно активирует низкоуровневый Kernel ETW (полный перехват файловых операций, обращений к реестру и детальной сетевой активности ядра).

---

## 3. Сценарий работы

### Шаг 1. Выбор файла и каталога результатов
1. В строке **«Целевой исполняемый файл (.EXE)»** нажмите кнопку **«Обзор...»** и выберите анализируемый исполняемый файл.
2. Программа автоматически:
   * Вычислит канонический путь к файлу.
   * Рассчитает криптографический хеш SHA-256.
   * Проверит наличие и статус цифровой подписи Authenticode (имя издателя, доверенный статус).
   * Отобразит эти данные во вкладке **«Обзор»**.
3. В строке **«Папка результатов сессии»** укажите директорию, куда будут сохраняться сессии анализа (по умолчанию `%USERPROFILE%\ExeScope_Results`).

### Шаг 2. Настройка ограничений
* При необходимости включите или отключите опцию **«Сохранять артефакты»** (сохранение файлов, измененных программой).
* Задайте предельный размер одного файла и суммарный дисковый лимит (по умолчанию 10 МБ и 100 МБ).
* Опционально отметьте **«Захват пакетов (PCAPNG)»**, если требуется сохранить дамп сетевого трафика.

### Шаг 3. Переход в режим ожидания запуска
1. Нажмите зеленую кнопку **«▶ Ожидать запуск»**.
2. Статус приложения изменится на **«Ожидание запуска»**.
3. На этом этапе ExeScope **заранее активирует** необходимые источники событий (ETW, отслеживание сокетов и процессов), чтобы не упустить самые первые события инициализации программы.
4. **ExeScope намеренно не запускает выбранный файл самостоятельно!**

### Шаг 4. Самостоятельный запуск исследуемой программы
1. Самостоятельно запустите выбранный `.exe` (двойным кликом в Проводнике или через командную строку).
2. ExeScope мгновенно обнаружит запуск по совпадению канонического пути образа:
   * Проверит соответствие PID и времени создания процесса.
   * Если файл был изменён на диске уже после выбора в анализаторе, в отчёте и журнале появится предупреждение о нарушении целостности.
   * Статус анализатора перейдет в **«Запись событий...»**.
   * Будет создана изолированная папка сессии: `session_YYYYMMDD_HHMMSS_PID<ID>`.

### Шаг 5. Мониторинг в реальном времени
Во время работы исследуемого приложения доступны следующие вкладки:
* **«Дерево процессов»** — интерактивная иерархия целевого процесса и всех порожденных им дочерних процессов (включая PID, Parent PID, командные строки и статус).
* **«Файлы»** — операции создания, открытия, чтения, записи, переименования и удаления файлов.
* **«Реестр»** — создание и удаление ключей реестра, изменение значений.
* **«Сеть»** — активные TCP-соединения, UDP-эндпоинты и DNS-запросы с подтвержденной привязкой к PID.
* **«Сохранённые артефакты»** — список сохраненных копий созданных/измененных файлов с хешами SHA-256 и статусами.
* **«Диагностика»** — системные сообщения, предупреждения о переполнении очередей и ограничениях.

### Шаг 6. Завершение сессии и формирование отчёта
* Анализ продолжается, пока работает основной процесс или хотя бы один из его дочерних процессов.
* При завершении всех отслеживаемых процессов сессия автоматически финализируется.
* Вы также можете в любой момент нажать кнопку **«⏹ Остановить запись»** (это завершит сбор данных, **не прерывая** выполнение самой исследуемой программы).
* Нажмите кнопку **«📁 Открыть папку результатов»**, чтобы перейти к файлам сессии.
* Нажмите **«📊 Сформировать отчёт»**, чтобы сгенерировать или обновить автономный HTML-отчёт.

## 4. Структура сохраненных результатов

Внутри папки каждой сессии формируется стандартизованный набор файлов:

| Файл | Описание |
| :--- | :--- |
| `session.json` | Параметры анализа, хеш SHA-256, метаданные цифровой подписи, временные метки UTC, статус привилегий и ограничения источников. |
| `events.jsonl` | Полный хронологический поток событий в формате JSON Lines (NDJSON). |
| `process-tree.json` | Иерархическое дерево всех зафиксированных процессов (корень, потомки, аргументы командной строки). |
| `artifacts/` | Каталог с сохраненными копиями файлов, созданными или измененными процессами. Имена файлов нормализованы для защиты от path traversal. |
| `artifacts-index.jsonl` | Реестр артефактов: оригинальный путь, безопасное имя, хеш SHA-256, размер, результат и причина (если файл был заблокирован/удален). |
| `network.pcapng` | Сетевой дамп в стандартном формате PCAPNG (если был активирован сетевой захват). Читается в Wireshark. |
| `report.html` | Автономный интерактивный отчет со встроенными стилями и скриптами (не требует подключения к Интернету). |
| `diagnostics.log` | Журнал диагностики, системные предупреждения, ошибки и фиксация потерь буфера. |

> 🔒 **Безопасность отчётов и артефактов:**
> * Все строки, полученные от исследуемого приложения (командные строки, имена файлов, ключи реестра), строго экранируются в HTML (`WebUtility.HtmlEncode`), исключая сохраненные XSS-атаки.
> * Сохраненные артефакты никогда не открываются и не исполняются автоматически.
