# Руководство пользователя ExeScope

## 1. Назначение и безопасность

ExeScope предназначен для наблюдения за поведением исполняемых файлов (`.exe`) в Windows во время их запуска и работы.

> **Важное предупреждение**: ExeScope не изолирует операционную систему от действий исследуемой программы. Это именно инструмент наблюдения, а не песочница.
>
> Запускайте анализ только внутри чистой тестовой виртуальной машины (VirtualBox, VMware, Hyper-V или Windows Sandbox):
> - До запуска создайте снимок (Snapshot) системы.
> - Убедитесь, что внутри виртуалки нет личных данных, рабочих аккаунтов, токенов и сетевых дисков хоста.
> - После каждого анализа откатывайте систему к исходному состоянию.

## 2. Системные требования

- ОС: Windows 10 (версия 1809+) или Windows 11 (x64 / ARM64).
- Среда выполнения: .NET Desktop Runtime 8.0 (или .NET 8 SDK при сборке из исходников).
- Уровень привилегий:
  - Обычный пользователь: доступно построение дерева процессов через Toolhelp32, привязка сетевых сокетов через Win32 IP Helper и сохранение артефактов из пользовательских каталогов.
  - Администратор: дополнительно активирует Kernel ETW для перехвата системных вызовов к файловой системе и реестру.

## 3. Сценарий работы

### Шаг 1. Выбор файла и каталога результатов
1. В поле «Целевой исполняемый файл (.EXE)» нажмите «Обзор...» и укажите исследуемый файл.
2. Программа автоматически:
   - Рассчитает канонический путь к файлу.
   - Вычислит хеш SHA-256.
   - Проверит наличие и статус цифровой подписи Authenticode.
   - Выведет полученные данные во вкладку «Обзор».
3. В поле «Папка результатов сессии» укажите каталог для сохранения результатов (по умолчанию `%USERPROFILE%\ExeScope_Results`).

### Шаг 2. Настройка ограничений
- Включите или отключите сохранение артефактов (копирование созданных/измененных файлов).
- При необходимости измените лимиты: максимальный размер одного файла и общий объем хранилища сессии.
- Отметьте «Захват пакетов (PCAPNG)», если требуется дамп сетевого трафика.

### Шаг 3. Режим ожидания
1. Нажмите зеленую кнопку «▶ Ожидать запуск».
2. Статус сменится на «Ожидание запуска».
3. На этом шаге ExeScope активирует фоновые сборщики событий, чтобы не упустить ранние события инициализации программы.
4. Сам анализатор выбранный файл не запускает.

### Шаг 4. Запуск исследуемой программы
1. Запустите выбранный `.exe` самостоятельно (двойным кликом в Проводнике или через терминал).
2. Анализатор определит запуск по совпадению канонического пути образа:
   - Проверит соответствие PID и времени создания процесса.
   - Если файл на диске изменился после выбора, программа выдаст предупреждение.
   - Статус перейдет в «Запись событий...».
   - Будет создана папка сессии: `session_YYYYMMDD_HHMMSS_PID<ID>`.

### Шаг 5. Мониторинг в реальном времени
Во время работы исследуемого приложения данные раскладываются по вкладкам:
- «Дерево процессов»: интерактивная иерархия целевого процесса и всех его потомков (PID, Parent PID, командная строка, статус).
- «Файлы»: операции создания, открытия, чтения, записи, переименования и удаления файлов.
- «Реестр»: ключи реестра и изменения значений параметров.
- «Сеть»: активные TCP-соединения, UDP-сокеты и DNS-запросы с привязкой к PID.
- «Сохранённые артефакты»: скопированные файлы с хешами SHA-256 и статусом сохранения.
- «Диагностика»: системные логи анализатора, предупреждения и потери буфера при нагрузке.

### Шаг 6. Завершение сессии и отчет
- Анализ идет, пока работает основной процесс или хотя бы один из его дочерних процессов.
- Когда все отслеживаемые процессы завершаются, запись останавливается автоматически.
- Запись также можно остановить вручную кнопкой «⏹ Остановить запись» (это завершит сбор данных, не закрывая сам исследуемый процесс).
- Кнопка «📁 Открыть папку результатов» открывает каталог с данными сессии в Проводнике.
- Кнопка «📊 Сформировать отчёт» обновляет и открывает автономный HTML-отчет.

## 4. Структура результатов

В папке сессии формируется следующий набор файлов:

| Файл | Описание |
| :--- | :--- |
| `session.json` | Параметры анализа, хеш SHA-256, метаданные подписи, временные метки UTC и ограничения источников |
| `events.jsonl` | Полный хронологический поток событий в формате JSON Lines |
| `process-tree.json` | Иерархическое дерево всех зафиксированных процессов |
| `artifacts/` | Каталог с копиями файлов, созданными или измененными процессами |
| `artifacts-index.jsonl` | Реестр артефактов: оригинальный путь, безопасное имя, SHA-256, размер и статус |
| `network.pcapng` | Сетевой дамп в формате PCAPNG для анализа в Wireshark |
| `report.html` | Автономный интерактивный отчет (работает без подключения к сети) |
| `diagnostics.log` | Журнал диагностики, системные сообщения и фиксация потерь буфера |
